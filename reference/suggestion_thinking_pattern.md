# Thinking Pattern Suggestion

## Process Outline

1. Receive user input
2. Think about what the user input means (context)
3. Check if tool use is necessary
   1. If yes, consider the appropriateness of the necessary tool/s
      1. Use tools as necessary
   2. If no, continue to next step
4. Think about an appropriate response using available retrieved sources.
5. Respond

## Explaination

Thinking about each step provides more robust reasoning for a particular response rather than just finding the closest matching response.

Right now this introduces more latency into the flow, but is acceptable.

As models get smaller and faster, and as this project expands, this will become less noticeable while maintaining high quality responses.
